# Attention 与 Transformer：一些理解

## 1. Attention 与 CNN：都在提特征，但权重的逻辑不同

Attention 与 CNN 的目的都是为了提取特征，但在逻辑本质上的实现存在不同。

- **Attention**：权重由输入的 query 与 key 动态算出。常用标量注意力权重形式为：

```math
W_{ij} = \frac{1}{Z} \exp\left(\frac{q_i \cdot k_j}{\sqrt{d}}\right)
```

- **CNN**：卷积核在训练收敛后是**静态权重**（相对单次前向而言不随空间位置再变），因此同一套滤波器在整个特征图上复用，提取的是一类固定的局部模式。

## 2. Mamba 与 Transformer：状态演化 vs 全局加权

本质区别在于：Mamba 基于**状态空间模型**，Transformer 基于**自注意力**。

- **状态空间（离散直觉）**：

```math
x_{t+1} = A_t x_t + B_t u_t
```

这是沿时间（或序列维）的线性递推关系。

- **自注意力**：

```math
x_{t+1} = \sum_{i=1}^{n} \alpha_{ij} x_i
```

其中 $`\alpha_{ij}`$ 为注意力权重，由当前 token 与全体 token 的关系经 $`Q,K`$ 算得。

这里 $`A_t`$、$`B_t`$ 是状态转移与输入矩阵；$`\alpha_{ij}`$ 则是「谁该看谁」的耦合强度。

## 3. 从底层理解 Attention：前向在算什么，反向在改什么（与梯度的连接）

### 3.1 Transformer 里谁在当「Query」

在标准自注意力里，**query 并不是人手工喂进去的语义问题**，而是由输入序列经线性层映射得到：$`Q = X W_Q`$，$`K = X W_K`$，$`V = X W_V`$。相似度仍是向量内积（再缩放），只是这些向量已经是**可学习投影**之后的空间里的表示。

在机器看来，图像块、词、像素点最终都只是一串**特征数值**；所谓「相似」就是内积或大模型里更一般的可学习度量——模型并不先验地「懂」语义，而是被训练成在数值空间里**对齐**对任务有用的模式。

### 3.2 前向传播：一张计算图（DAG）

一次前向从输入到 loss，框架（如 PyTorch）会在后台搭一张**有向无环图（DAG）**：

- 每个参与运算的 **Tensor** 是图上的节点；
- 每个算子（`matmul`、`softmax`、`+`、`*` 等）是一条边，并记录在 tensor 的 `grad_fn` 上；
- 为了之后求导，前向还会**缓存**必要中间量（例如对 $`y = a \odot b`$ 求 $`\partial y/\partial a`$ 时要记住 $`b`$）。

自注意力块里典型链路是：

```math
S = \frac{Q K^\top}{\sqrt{d}},\quad A = \mathrm{softmax}(S),\quad O = A V
```

（多头时只是并行多组这样的线性代数。）

### 3.3 `loss.backward()`：反向模式自动微分与链式法则

`loss.backward()` 触发的是**反向模式自动微分**：从标量 loss 出发，沿 `grad_fn` 指针从末节点往叶子参数走。对每个算子，实现里已经写好了局部雅可比或标量链式规则；与上游传来的梯度相乘后**继续往前传**。

复合函数 $`L(g(f(x)))`$ 的链式法则在符号上就是：

```math
\frac{\partial L}{\partial x}
=
\frac{\partial L}{\partial g}
\cdot
\frac{\partial g}{\partial f}
\cdot
\frac{\partial f}{\partial x}
```

在实现上，这是图上亿万次「上游梯度 × 局部导数」的累积；对 **`matmul(Q, K^T)`** 这类运算，同样走矩阵乘法的标准反向公式，把误差分摊到 $`Q`$ 与 $`K`$ 两侧，再进一步传到 $`W_Q`$、$`W_K`$。

**叶子节点**（`requires_grad=True` 的 $`W_Q,W_K,W_V`$ 等）最终把结果写入 `.grad`，供优化器使用。

### 3.4 训练循环如何把「随机对齐」雕成「有用对齐」

与对话里三步对应：

1. **前向**：`output = model(input)`，`loss = criterion(output, target)` —— 先算出误差有多大。
2. **反向**：`loss.backward()` —— 把「总误差该谁负责」按链式法则分到每个参数上，得到**纠错方向**（梯度）。
3. **更新**：`optimizer.step()` —— 按梯度（以及 AdamW 等规则里的动量、权重衰减）**实际挪动**参数；`loss.backward()` 只负责「往哪推」，优化器负责「推多远」。

训练初期 $`Q`$、$`K`$ 几乎是乱的；若某次随机更新让**对任务有利的 token 对**在内积上更突出、从而 loss 下降，反向传播就会把**强化这种投影关系**的信号写进 $`W_Q`$、$`W_K`$ 的梯度里。大量「试错—算 loss—反传—更新」之后，参数就被「雕」成能稳定完成某种**向量对齐**（对分类、重建、下一词预测等目标而言）的形状。用对话里的比喻：前向像蒙眼摸象，loss 像挨打，反传像追责，优化器像改过——**不需要**模型先验理解像素或词义，数值上自洽即可。

### 3.5 为什么要 `optimizer.zero_grad()`

`.grad` 在框架里往往是**累加**而非每步覆盖：同一参数若在图里多条路径被用到，需要把各路径梯度**求和**。因此每个 iteration 开头要 `optimizer.zero_grad()`，清掉上一轮「纠错指南」，否则会混进陈旧梯度。

### 3.6 和「递归序列模型」对比时的梯度视角（便于对照 Mamba / RNN）

- **Transformer 注意力**：一步内是**全局两两比较**（$`O(n^2)`$ 的注意力矩阵），梯度通过 softmax、对 $`QK^\top`$ 的 matmul、再对 $`W_Q,W_K`$ 传回去；**不依赖**跨步长的递推链，因而没有经典 RNN 那种「时间步很长时 BPTT 链特别长」的同构问题，但会面临 **显存与算力**、以及 **softmax 极端尖锐** 时优化上的困难（梯度主要集中在少数位置上）。
- **Mamba / SSM 一类**：离散形式 $`h_t=\bar{A} h_{t-1}+\bar{B} x_t`$，$`y_t=C h_t + D x_t`$，反传时梯度沿 $`h_t \to h_{t-1}`$ **递归回传**；序列极长时，纯递推既慢又容易出现**梯度消失/爆炸**（与反复乘以状态转移相关），工程上会用**并行扫描、重计算**等技巧换空间或换时间——这和 Transformer 用 checkpoint、FlashAttention 等做显存与反传优化是同一类「底层实现问题」，但瓶颈来源不同。

若用对话里「闸门 / 选择性」的直觉来对照：**Mamba 里**梯度会追问 $`\Delta,B,C`$ 等由输入生成的量是否合适；**Attention 里**梯度会追问：** softmax 分给 token $`j`$ 的权重是否过大/过小**，并通过 $`W_Q,W_K`$（以及值通路 $`W_V`$）调整，使「该互相看见」的位置在内积上更容易拿到大权重。
